# PasteLite 0.4.0 开发计划：收藏库与常用片段

更新日期：2026-11-06（Asia/Shanghai）

研发基线：`main` / `7c24d6c`，PasteLite 0.3.2 / build 32

目标版本：0.4.0 / build 40，macOS 12+，Apple Silicon 与 Intel

状态：核心功能已实现；Debug 142、Release 141 个测试通过，双架构发布包已生成。实机交互验收限制见 [0.4.0 验收记录](acceptance-0.4.0.md)。

## 1. 版本目标

完成“保存 → 整理 → 搜索 → 粘贴”的常用内容流程，让用户可以长期维护命令、提示词、回复、链接、颜色、图片和文件引用。

0.3.2 已经具备历史采集、搜索、分类预览、直接粘贴和基本隐私管理。本版解决三个缺口：置顶内容缺少用户分组，内容缺少可记忆的名称，常用文本缺少创建与编辑入口。

竞品对照采用三个具体参考：Clipy 的独立片段库、EcoPaste 的一级分组、Maccy 的命名与快速调用。继续使用现有原生列表和预览结构，详细依据见 [开源工具功能结构对照](opensource-comparison-2026-11-06.md)。

本版必须交付收藏、分组、命名、文本片段、搜索与键盘调用，以及数据迁移和对应验收。**导入导出安排在紧随其后的 0.4.x；OCR、多选与 Paste Stack 属于后续功能版本。**

## 2. 功能结构与交付范围

```text
PasteLite 0.4.0
├─ 历史：自动记录、类型筛选、内容预览、单项粘贴
├─ 收藏库
│  ├─ 全部收藏 / 未分组 / 自建一级分组
│  ├─ 原样收藏：名称、来源、完整复制格式
│  └─ 文本片段：名称、正文、文本/代码类型、编辑
├─ 快速复用：搜索、键盘选择、复制、直接粘贴、纯文本
└─ 管理：旧置顶迁移、删除撤销、容量与清理、错误反馈
```

| 编号 | 功能 | 0.4.0 交付要求 |
| --- | --- | --- |
| F1 | 独立收藏库 | 支持收藏普通文本、代码、链接、颜色、图片、文件引用；载荷独立保存；普通历史淘汰不影响收藏 |
| F2 | 一级分组 | 新建、重命名、删除、移动内容；提供“全部收藏”和“未分组”；每个内容最多属于一个自建分组 |
| F3 | 自定义名称 | 收藏与片段可以命名；名称参与搜索；名称不改变实际复制内容 |
| F4 | 常用文本片段 | 手动新建多行文本或代码；从历史创建片段；编辑片段正文；原始历史和原样收藏保留 |
| F5 | 搜索与快速调用 | 面板切换“历史 / 收藏”；分组与类型筛选可同时生效；复用现有复制、粘贴和纯文本行为 |
| F6 | 生命周期与兼容 | 旧置顶迁移、删除撤销、重启持久化、清理范围、机密内容规则及保存失败处理 |

本版的范围外事项：嵌套分组、多标签、拖拽排序、固定到单个收藏的全局快捷键、富文本正文编辑、模板变量、缩写展开、同步、AI 改写和外部代理接口。

## 3. 内容模型与产品规则

### 3.1 原样收藏与文本片段

| 内容 | 保存方式 | 可以修改的部分 | 粘贴结果 |
| --- | --- | --- | --- |
| 原样收藏 | 保存当时的完整剪贴板格式和载荷 | 名称、分组 | 沿用原始格式；纯文本操作采用已有转换规则 |
| 文本片段 | 独立保存纯文本正文，类型为文本或代码 | 名称、分组、正文、文本/代码类型 | 以纯文本写入剪贴板 |

从历史加入收藏时，提供两个明确入口：

- **加入收藏：** 原样保存，默认使用原内容标题，可输入名称并选择分组。
- **保存为文本片段：** 仅对可提取文字的文本/代码内容提供，打开带有正文的编辑器。

对原样文字收藏使用“创建文本片段”时，保存新的可编辑副本。编辑已有片段则更新该片段。富文本转换为片段时，在编辑器说明将以纯文本保存，原始内容保留。

新片段默认是文本，用户可以切换为代码；不因正文看起来像网址或颜色而自动改变片段类型。图片、链接、颜色和文件收藏只编辑名称与分组。

### 3.2 分组、命名与重复内容

- 分组采用一级结构，默认按创建顺序排列；“全部收藏”和“未分组”是内建视图，不能改名或删除。
- 分组名称去除首尾空白后为 1–40 个字符；不允许与内建视图或已有分组重名，英文比较忽略大小写。
- 内容名称为 1–120 个字符，允许不同内容使用相同名称；缺省名称从源标题生成并截短。
- 同一份原始内容重复加入原样收藏时，定位已有收藏，保留用户名称和分组；移动分组需要明确执行移动操作。
- 不对手动片段按正文自动去重，允许同一正文以不同名称或用途保存。
- 删除分组需要确认，组内内容移到“未分组”；不删除内容。分组删除不进入条目的五秒撤销窗口。
- 历史复用继续刷新最近时间并前移；收藏复用只更新自己的最近使用和使用次数，不新增历史、不改变保存时间或列表排序。

### 3.3 生命周期与清理

| 操作 | 历史 | 收藏与片段 |
| --- | --- | --- |
| 调整历史容量 | 按历史规则淘汰 | 保留，数量不占历史上限 |
| 删除一条历史 | 删除该历史，提供撤销 | 已保存的副本保留 |
| 删除一条收藏/片段 | 不主动删除源历史 | 删除所选内容，提供撤销 |
| 清空普通历史 | 按确认范围清理 | 保留内容和分组 |
| 清空收藏库 | 保留历史 | 确认后删除全部收藏、片段和自建分组 |
| 开启清空退出 | 清除全部历史，包括旧机密置顶项 | 同时清除内容、载荷和分组 |
| 再次复制相同源内容 | 正常去重与记录 | 不覆盖已保存副本、名称或分组 |

文件收藏保存文件引用，沿用当前行为，不复制文件本体。文件移动或删除后显示不可用，提供已有路径信息；不自动寻找并替换为同名文件。

机密内容禁止加入永久收藏或转换为片段。旧机密置顶项保留在历史中，继续遮罩并按原 `expiresAt` 到期；迁移、复用和撤销都不能延长期限。这里的机密规则沿用现有剪贴板标记，不声称能够识别所有未标记的秘密。

## 4. 界面与操作

### 4.1 主面板

- 顶部增加“历史 / 收藏”切换，复用列表、详情预览和底部操作区域。
- 收藏模式增加分组选择器、“新建片段”和分组管理入口；完整模式与 520 pt 紧凑模式均使用选择器，长名称截断并提供完整提示。
- 普通内容的置顶操作升级为“加入收藏”。历史中的旧普通 Pinned 区域和筛选入口由收藏模式承接，历史按最近时间显示；旧机密项继续保留原保护规则。
- 历史行显示已原样收藏的状态；显示状态按原内容指纹判断，不能依赖易变化的源记录 ID。
- 全局快捷键正常呼出时显示历史、清空查询，保留历史类型筛选；收藏记住上次使用的有效分组。
- 一次面板展示期间，切换模式保留各自的查询、筛选和有效选择；重新呼出不恢复旧查询。
- 收藏为空时提供“新建片段”和“查看历史”；搜索无结果时提供清除查询和查看全部收藏入口。

### 4.2 搜索、排序和选择

- 收藏搜索匹配名称、可提取正文、链接/文件路径及来源应用名称；默认支持中文和英文子串，英文忽略大小写。
- 分组、类型筛选和搜索同时生效。没有选择具体分组时搜索全部收藏。
- 无查询时按名称自然顺序排列，以稳定 ID 作为同名排序的兜底；使用后不移动收藏位置。
- 有查询时按“名称完全匹配 → 名称前缀 → 名称包含 → 正文/来源匹配”排列，同层保持名称与 ID 顺序。
- 重命名或数据刷新后，仍存在于结果中的选中 ID 保持选中；删除后选择原位置的相邻项。
- 搜索、分组或类型条件变化时选择首项。复制快捷键和数字快捷键始终使用同一份当前结果。

### 4.3 片段编辑器

采用附着于面板的原生 sheet，提供名称、分组、文本/代码类型、正文、保存和取消。代码采用等宽字体，正文支持多行与滚动。

- 正文允许内部空行，保存时不自动裁掉首尾内容；仅空白的正文不保存。
- 可编辑正文上限为 1 MiB UTF-8；超过上限的历史仍可原样收藏，创建片段入口说明限制。
- 保存失败保留草稿和编辑焦点，允许重试；成功后显示目标收藏分组，清空该视图查询、重置类型并选中保存的内容。
- 未保存修改在取消、关闭或退出时提供“保存 / 放弃 / 继续编辑”。
- 编辑器打开后不触发列表粘贴动作，也不把 PasteLite 或其 sheet 更新为外部粘贴目标。

### 4.4 键盘与反馈

| 场景 | 按键 | 行为 |
| --- | --- | --- |
| 面板 | 全局现有快捷键 | 呼出/关闭；保留用户当前配置 |
| 面板，无 sheet | Ctrl-Tab / Ctrl-Shift-Tab | 切换历史与收藏；普通 Tab 继续使用原生焦点导航 |
| 列表与搜索 | 方向键、Cmd-Up/Down | 沿用当前选择与跳转行为 |
| 列表与搜索 | Return、Cmd-1…9 | 对当前项执行配置的复制/粘贴动作 |
| 列表与搜索 | Option-Return | 反转当前纯文本偏好 |
| 收藏模式 | Cmd-N | 新建片段 |
| 收藏中的片段 | Cmd-E | 编辑片段；原样收藏通过 Actions 创建文字副本 |
| 普通历史项 | Shift-Cmd-P | 未收藏时加入；已收藏时移出对应原样收藏并提供撤销；机密内容不能永久收藏 |
| 列表 | Cmd-C / Cmd-Backspace / Cmd-Z | 复制、删除、撤销；文本选区和文本编辑优先走原生行为 |
| 编辑器 | Return / Cmd-Return | 正文换行 / 保存 |
| 编辑器 | Tab、Cmd-C、Cmd-Z、输入法组合 | 原生输入、焦点、复制与文本撤销 |
| 面板 | Escape | 先处理编辑器或 Actions，再清查询，最后关闭 |

复制和粘贴继续静默完成。保存、移动和删除在当前界面体现结果；错误可见，Undo 与错误并排。动作开始前缺少辅助功能权限或粘贴目标时主动作回退为复制，按钮文案与实际动作一致；执行期间的目标、权限或剪贴板变化走现有取消与错误处理，不改投其他目标。

撤销沿用五秒窗口，并统一支持历史项与收藏项，保存最近一次删除的完整载荷。失败保留载荷直到原窗口到期。清空操作结束当前撤销窗口，清空前启动的任务不能恢复被清理内容。

## 5. 数据与代码实现方案

### 5.1 数据结构

在现有 SQLite 中新增收藏相关表，schema 从 v3 升到 v4。仍由一个 repository actor 拥有数据库连接，统一执行历史、收藏、迁移和清空事务。

| 结构 | 主要字段与约束 |
| --- | --- |
| `library_groups` | UUID、名称、创建/更新时间；名称唯一；内建视图不占表记录 |
| `library_items` | 独立 UUID、可空分组 ID、原样/片段类型、内容类型、用户名称、预览/搜索文字、来源、保存/更新时间、最近使用、使用次数、修订号 |
| 来源信息 | 原始内容 hash 和可选源历史 ID；源 ID 只作来源记录，不用于级联删除或内容解析 |
| `library_assets` | 收藏 ID、原 item index、pasteboard type、BLOB、字节数；随收藏删除；独立保存完整原始载荷 |

原样收藏按原始内容 hash 唯一；片段以自己的 UUID 标识。片段编辑后更新内容 hash、修订号和搜索文字，不修改来源内容的 hash。删除分组用事务把条目归回未分组。

收藏列表只加载元信息，附件按需读取，缩略图延续有预算的缓存。原样收藏沿用当前每个表示 20 MiB、每项总计 64 MiB 的限制；不通过只保存部分格式绕过限制。

第一版使用独立载荷快照，不开展历史与收藏共享 BLOB 的重构。Storage 页面分别显示历史和收藏数量/载荷大小，物理数据库大小仍采用实际文件统计。

### 5.2 旧置顶迁移

迁移必须满足原子性、可重试和不重复创建：

1. 读取已有 schema 版本，沿用旧版本字段补齐，再在一次事务中建立 v4 收藏结构。
2. 把未过期、非机密的普通置顶项复制为“未分组”原样收藏，保留完整格式、来源、名称默认值和已有使用次数。
3. 保留原历史记录与资产；普通旧置顶状态由收藏承接。迁移过程不执行容量淘汰，后续正常捕获或调整容量才应用普通历史上限。
4. 旧机密置顶不进入收藏，保持原遮罩、到期和保护状态。
5. 事务成功后才写入 `user_version = 4`；失败回滚，禁止展示为已完成迁移。再次启动不产生重复收藏。

当前 `HistoryRepository.migrate` 每次将 `user_version` 写成 3。开发时需要改成按版本递进的迁移入口，避免再次打开 v4 库时重置版本。

收藏必须真实持久化。数据库不可用时禁用新的收藏/片段保存并显示重试入口；不能将内存保存显示为长期保存成功。历史现有内存回退仍需明确提示。清空退出必须确认磁盘数据已清除，失败时保留应用并允许重试。

### 5.3 涉及的代码与职责

以下新增文件名为实施建议，开发时可以按现有模块边界调整。

| 位置 | 主要任务 |
| --- | --- |
| [ClipboardItem.swift](../Sources/PasteLite/Models/ClipboardItem.swift)；新增 `LibraryItem.swift`、`LibraryGroup.swift` | 定义原样收藏、片段、分组和带数据来源的选择标识 |
| [HistoryRepository.swift](../Sources/PasteLite/Stores/HistoryRepository.swift) | v4 迁移、收藏/分组 CRUD、原样去重、载荷解析、使用记录、清空事务 |

| [AppServices.swift](../Sources/PasteLite/App/AppServices.swift) | 创建唯一 repo 并注入两个 Store，避免两个 actor 各自打开同一数据库 |
| [AppState.swift](../Sources/PasteLite/App/AppState.swift)、[AppPreferences.swift](../Sources/PasteLite/Stores/AppPreferences.swift) | 模式、各自的查询/筛选/选择、上次收藏分组及统一当前结果 |

| 新增 `SnippetEditorView.swift`、`LibraryGroupEditorView.swift` | 编辑、校验、草稿、保存失败重试及焦点处理 |
| [HistoryPanelController.swift](../Sources/PasteLite/Views/HistoryPanelController.swift)、[PasteService.swift](../Sources/PasteLite/Services/PasteService.swift) | 从当前数据域解析选中内容；sheet 键盘分发；统一复制/粘贴与回退 |
| [SettingsView.swift](../Sources/PasteLite/Views/SettingsView.swift)、[AppDelegate.swift](../Sources/PasteLite/App/AppDelegate.swift) | 收藏存储统计、清空确认与全量清空退出 |

`PasteService` 当前的懒加载只通过 `HistoryStore.resolve` 查历史 ID。需要增加统一载荷解析协议或注入解析闭包，让收藏和片段经过相同的剪贴板、取消、权限和焦点校验。

共享预览也必须采用正确的载荷来源；不能只复用行 UI，而让收藏图片继续按历史 ID 读取。编辑片段后以独立 ID、内容 hash 和修订号更新预览，旧异步结果不能覆盖新内容。

UI 在事务提交后应用快照。更新修订号、异步请求 token 和清空 generation，覆盖保存/编辑/撤销晚于清空返回的情况。使用次数文案采用“使用”，记录成功的复制或粘贴，不能把复制次数标成“Pasted”。

## 6. 开发批次与工作量

按一名熟悉当前 Swift/AppKit 代码的开发者估算，约 **9–14 个开发工作日**。这是工作量估算，实际进度以每批验收为准；旧问题返修和外部兼容机器准备会影响日历时间。

| 批次 | 任务 | 产出与退出条件 | 估算 |
| --- | --- | --- | --- |
| M0 基线 | 核对 0.3.2；实测呼出、快速应用切换、文本/图片复制和粘贴；记录性能 | 基线记录、可复现的问题清单、合成数据集 | 0.5–1 天 |
| M1 数据 | 数据模型、共享 repo、v4 迁移、分组/收藏操作、生命周期 | 迁移完整、重复安全、事务失败回滚；源历史删除后收藏可解析 | 2–3 天 |
| M2 面板 | 历史/收藏切换、分组、命名、检索、排序、空状态 | 原样内容可保存、查找、预览和复用；选择与数字快捷键一致 | 2–3 天 |
| M3 片段 | 手动创建、历史文字副本、编辑器、草稿与错误重试 | 中文输入、换行、保存、重启后读取和片段粘贴完整 | 1.5–2 天 |
| M4 集成 | 撤销、清空退出、键盘/VoiceOver、小屏、缓存与性能 | 任务取消和清空竞态通过；真实交互及性能满足要求 | 2–3 天 |
| M5 封版准备 | Debug/Release 检查、双架构包、升级与更新回归、文档 | 形成 0.4.0 验收记录和可复验的候选包 | 1–2 天 |

M1 完成后进入 M2；M2 提供的导航、选择和解析能力供 M3 使用。M4 汇总前三批的行为回归，M5 使用最终源码和候选包，不以早期构建替代。

开发分支使用 `codex/0.4.0-library`，每批围绕表中的产出提交。候选封版时统一应用、脚本、CI 和版本测试中的 0.4.0 / build 40。

## 7. 测试与验收

### 7.1 必须自动验证的场景

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 旧库升级 | v1/v2/v3 迁移至 v4；置顶原样内容、所有 BLOB 和使用信息完整；重复启动无重复；注入失败后旧库仍完整 |
| A02 | 内容独立 | 源历史删除、淘汰或同 hash 重新捕获后，收藏仍能读取原完整载荷；名称、分组不变 |
| A03 | 分组 | 重名校验、移动、重启；删除组后所有内容回到未分组，载荷不丢失 |
| A04 | 片段 | 中文、英文、代码、空行与正文边界正确；超限不保存；编辑不改变源历史或原样收藏 |
| A05 | 持久化失败 | 保存/改名/移动失败不显示成功；草稿或原状态保留；恢复存储后可重试 |
| A06 | 检索与选择 | 名称/正文/路径/来源匹配；分组与类型组合；重排保留选择、删除选择相邻项、条件变化选首项 |
| A07 | 剪贴板与目标 | 收藏和片段走既有权限、焦点、changeCount 和取消检查；失败不发送错误目标的 Paste |
| A08 | 撤销与清空 | 完整载荷可恢复；失败可在原窗口重试；清空前的异步保存和 Undo 不能恢复已清理内容 |
| A09 | 机密内容 | 禁止永久收藏及片段入口；旧机密置顶不迁移；重用不续期；清空退出覆盖所有数据域 |
| A10 | 预览修订 | 编辑、切换或删除后旧载荷/图片/查询结果不覆盖当前项；缓存不跨数据域混用 |

新增测试建议按 `LibraryRepositoryTests`、`LibraryBehaviorTests`、`SnippetEditorTests` 组织，沿用已有临时数据库、独立剪贴板、受控时钟和故障注入方式。涉及 AppKit 共享状态的测试串行执行。

旧 pins/prune/clear 用例按本版收藏生命周期更新；既有跨应用粘贴、隐私标记、更新安装和回滚用例继续执行。新增测试覆盖实际风险和跨模块行为，不以实现细节的重复断言替代验收。

### 7.2 实机走查

完成以下完整流程，并记录系统版本、应用版本、权限状态和结果：

1. 创建“提示词”分组，从历史保存一个片段，命名、编辑、重启、搜索并粘贴。
2. 收藏带格式文本、代码、链接、颜色、图片和文件引用，验证原样复制与适用的纯文本操作。
3. 在 TextEdit、浏览器输入框、代码编辑器中真实粘贴；验证无权限、无目标、目标退出、目标切换和取消的反馈。
4. 编辑器中中文输入法、文本选区复制、原生撤销、Return 换行、Cmd-Return 保存及未保存关闭。
5. 键盘与 VoiceOver 完成模式切换、分组选择、行选择、编辑与主动作；紧凑模式和小屏中所有关键操作可达。
6. 删除分组、删除片段与 Undo、清空历史、清空收藏、重复退出；确认清理范围与实际磁盘记录一致。

0.3.2 对来源不稳定的快速复制采用跳过策略。M0 和最终走查都需记录其漏记范围，不能因新增收藏而放宽排除应用保护。

### 7.3 性能目标

使用 **5,000 条历史 + 200 条收藏**的合成数据，包括中文、英文、长文本和图片；另加 1 MiB 片段作为边界样例。

- 在记录的参考机器上，以 Release 构建测量至少 30 次操作：热呼出至可操作的 p95 目标 ≤200 ms，输入查询至结果更新的 p95 目标 ≤150 ms，包含采用的防抖时间。
- 元数据测试与附件边界测试分开记录数据大小；大附件加载可显示进度，加载期间搜索、关闭和取消仍可响应。
- 同一刷新只生成一次筛选/排序结果和计数，行渲染与键盘分发复用该结果；全文比较和附件处理避免阻塞主线程。
- 先测基线和候选版本，记录耗时、采样环境及差异；上述数字是验收目标，本计划没有已测结果。

### 7.4 封版条件

- Debug、Release 全量测试通过完整严格并发检查和 warnings-as-errors。
- arm64、x86_64 Release 构建、版本、签名、DMG 和升级迁移检查通过。
- 最终候选包通过应用内更新暂存、安装成功与回滚回归；用户历史、收藏和片段的升级路径完整。
- 0.4.0 核心流程的实机走查与 A01–A10 完成，发现的阻塞问题关闭，实际结果写入新验收报告。
- macOS 12、物理 Intel 与 Rosetta 的结果分别记录；没有对应机器的项目标为未验证，不能用构建或 Rosetta 结果冒充实机覆盖。
- README、CHANGELOG、发布说明说明置顶迁移、两类保存内容、清理范围及兼容性。

0.3.2 文档记录 Debug 112、Release 111 个测试通过，本计划未重新运行这些测试。0.4.0 的实际测试数和交互结果以开发后的验收记录为准。
