# PasteLite 0.2.1

PasteLite **0.2.1 (build 21)** — 2026-10-25.

## Fixes

- Clear History now discards older captures that are still being processed, so cleared records cannot reappear.
- Oversized clipboard content is rejected as a whole instead of being saved partially. The warning remains visible in history; limits remain 20 MiB per format and 64 MiB per capture.
- Keyboard navigation and filtering scroll the selected record into view. Mouse-selected rows stay in place, and reopening history returns to the first record.
- The global hotkey pauses during shortcut recording and resumes after completion, cancellation, closing the window, or switching away.
- The history directory is owner-only, with database, WAL, and SHM permissions repaired without replacing existing records.
- Release ZIPs omit copied extended attributes and resource forks.

## Compatibility and installation

- macOS 12.0 or later; separate Apple Silicon (`arm64`) and Intel (`x86_64`) downloads.
- Both builds are ad-hoc signed, without hardened runtime or notarization. If macOS blocks the first launch, choose Open Anyway in Privacy & Security, or Security & Privacy on macOS 12.
- The existing history database format is retained. These fixes do not require clearing existing history.

## Validation

- 57 automated tests passed in both Debug and Release with complete Swift concurrency checking and warnings treated as errors.
- Both DMGs were mounted. Bundle metadata, minimum macOS version, architecture, signatures, and file contents matched the staged apps and release ZIPs.
- Mounted-app startup passed natively for Apple Silicon and under Rosetta for Intel, using isolated application data. Database integrity and owner-only permissions were verified.
- Release bundles contain no local user build paths or history databases. ZIPs contain no AppleDouble files, resource forks, or Finder metadata files.
- Real cross-application paste acceptance and testing on macOS 12 / physical Intel hardware remain manual validation items.
