# PasteLite 0.4.1 发布 review

日期：2026-11-07。范围：v0.4.0 之后完整工作区变更，包括未跟踪的新文件；目标仅 arm64。

## 修复的问题

| 级别 | 问题与修复 | 回归 |
| --- | --- | --- |
| P1 | 粘贴等待阶段只检查清空 generation，无法发现单项编辑/删除。增加来源 ID/hash/revision 的同步检查，普通条目及模板转换结果在最终投递前都检查来源 | 等待激活期间编辑原片段，原样和转换结果均不发送 Paste |
| P1 | 合并复制的前置加载发生在剪贴板版本快照之前，可能覆盖用户刚复制的新内容。动作开始就固定 changeCount，并在最终写入校验所有来源 | 加载后剪贴板变化时拒绝合并写入 |
| P1 | 脚本取消只结束 shell，后台子进程仍可继续写文件。用独立进程组启动脚本，退出/失败/超时/取消均清理该进程组 | 子进程延迟写文件，取消后不产生文件 |
| P1 | 同步换文件夹沿用旧 receipts/outbox，使新目录漏数据；旧会话还可在 await 后继续确认发送或应用读取结果。记录目录身份并重建新目录初始事件，所有 I/O 恢复后重新检查会话和 generation | 换目录重新发送全部现存内容、清除旧 receipts，禁用时清掉未发送载荷 |
| P2 | 两台离线设备创建同名分组，各自只给远端组改名，最终不一致。由稳定 UUID 决定原名所有者，其余用完整 UUID 后缀消歧 | 交换事件后分组 ID → 名称映射一致 |
| P1 | 同一原样收藏的不同 UUID 收敛后，删除赢家仍可能由旧输家事件复活。删除事件携带内容 hash，接收端持久化删除标记并清理旧别名；未标为分组修改的旧组快照也不能重建已删除分组 | 删除先到、旧保存后到不恢复别名；旧输家重放不恢复内容；离线片段编辑不恢复已删除分组 |
| P2 | 模板展开先构造大字符串再检查上限，重复变量可能导致过量分配。替换前累计 UTF-8 输出大小并拒绝超限 | 缺失、重复、中文和超限变量回归 |
| P2 | 脚本重新运行失败仍保留上次输出，可能复制旧结果。运行前清空输出；OCR 取消同时调用 Vision 请求取消 | 原有脚本成功/失败/取消及真图 OCR 测试复验 |

同时检查本地 MCP 的 loopback 绑定、随机鉴权、只读工具与机密排除；备份格式校验、事务回滚；ARM 构建/更新器；明暗主题对比度和清空退出。没有新增第三方依赖，敏感模式扫描没有发现凭据或本机路径进入待提交文件。

## 发布条件

以上修复需通过最终 Debug/Release 严格并发与 warnings-as-errors、候选包挂载/隔离启动/安装回滚以及 ARM CI 后发布。最终测试与制品证据见 [验收记录](acceptance-0.4.1.md)。

最终结论：上述问题修复后通过 Debug 167 / Release 166 个测试、ARM CI 42272292398 及制品验证，发布提交 `83a1582`，已正式发布 v0.4.1。

保留既有明确限制：完整人工中文输入法、跨应用交互、VoiceOver、macOS 12 和实体双机同步未覆盖。这些不是自动测试通过的替代项，发布说明继续列出。
